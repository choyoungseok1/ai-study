## 배운 핵심 3가지

1. **"통과했지만 틀린 습관" 잡기 — 정수 조건은 정수로.** 시소 짝꿍에서 float 키 조회(`w*3/2 in cnt`)로도 통과했지만, 이는 무게 범위가 좁아 우연히 산 것. `%`로 나눠떨어짐 확인 후 `//`로 처리하는 구조가 옳다. 이모티콘 문제의 `//100`도 같은 원칙.
2. **그리디의 정당화는 "비용이 무엇으로 결정되는가"에서 나온다.** 택배 문제에서 왕복 비용은 그 왕복의 최원거리로만 결정되고, 배달·수거는 트럭에 동시에 실리지 않아 각각 cap씩 독립 소화 — 역순 누적 + 음수 여유 장부로 시뮬레이션 없이 O(n) 처리.
3. **규모 계산이 알고리즘을 고른다 (패턴 7 정착).** 시소(O(n²) 50억 → 무게 종류 순회 O(n)), 택배(n=10만 → 재순회 불가), 이모티콘(4^7×700 ≈ 1,100만 → 완전탐색 확정)까지, 이번 주 세 문제 모두 "탐색 범위 사전 계산 → 구조 결정"으로 풀림.

+α: 서빙 = 핵심 로직 위의 얇은 입출력 레이어(로직/전송 분리), Pydantic 스키마가 API 입력 계약으로 이어진다는 것 (7/7).
