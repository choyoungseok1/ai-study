# 2026-08-01 TIL

## 오늘 한 것
- `code/week16/rollcake_cut.py` — 프로그래머스 Lv2 "롤케이크 자르기" (일렬 토핑 배열을 두 조각으로 잘라 양쪽 토핑 종류 수가 같은 절단 지점의 개수 세기).
  - 왼쪽은 `set`(종류 집합), 오른쪽은 `Counter`(개수)로 두고, 절단선을 한 칸씩 밀며 넘어간 토핑을 왼쪽에 `add` / 오른쪽에서 `-= 1`(0이면 `del`)로 증분 갱신. 매 위치에서 `len(left_set) == len(right_counter)`면 카운트.
  - 시간 O(N) 1패스, 공간 O(K)(K=토핑 종류 수 ≤ 10,000). N=10^6이라 O(N²) 재계산은 즉사 → 증분 갱신으로 못 박고 시작.
  - 검증: 예제 + 경계 케이스(`[1,1,1,1]→3`, `[1]→0`, `[1,2]→1`) 6개 assert 전부 통과.

## 배운 개념
- **전체를 두 구간으로 쪼개는 문제 = 경계를 한 칸씩 밀며 증분 갱신**: 매 절단 위치마다 양쪽을 재계산하면 O(N²). 경계를 i→i+1로 옮길 때 실제로 바뀌는 원소는 딱 1개(왼쪽 추가/오른쪽 제거)임을 이용하면 O(N)으로 내려간다.
- **자료구조는 '저장할 데이터'가 아니라 '수행할 연산'이 정한다**: 같은 토핑을 담는데 왼쪽은 추가만 하니 "있냐/없냐"만 필요 → `set`, 오른쪽은 제거가 있으니 "몇 개 남았냐"가 필요 → `Counter`. 종류 수는 마지막 하나가 빠지는 순간에만 줄기 때문에 오른쪽을 `set`으로 `remove`하면 틀린다.
- **`del`로 카운트 0 키를 지워야 `len`이 '남은 종류 수'가 된다**: `-= 1`만 하면 0짜리 키가 남아 `len(right_counter)`이 "한 번이라도 등장한 종류 수"로 의미가 어긋난다. Counter는 없는 키에 `-=` 해도 KeyError가 아니라 -1이 되는(defaultdict) 성질이라 조용히 틀리기 쉬운 자리.

## 막힌 부분
- **투 포인터로 되나?** → 안 된다. 왼쪽 시작 0 고정, 오른쪽 끝 N-1 고정이라 움직이는 건 절단선 하나 → 자유도 1 → 포인터 1개. "양쪽이 동시에 변한다"는 투 포인터가 아니다. 투 포인터의 본질은 한쪽을 옮기면 다른 쪽이 되돌아갈 필요 없다는 단조성인데 여기엔 그 구조가 없다.
- **마지막 반복(왼쪽=전체, 오른쪽=빈 상태)이 왜 답을 안 망치나**: 유효한 절단이 아니지만 `len(right_counter)==0`이고 `len(left_set)>=1`이라 조건이 절대 성립 안 함 → 자동으로 걸러진다. "우연히 안 터진다"가 아니라 "왜 안 터지는지 증명 가능"해야 한다는 원칙(빈 오른쪽 vs 최소 1개 왼쪽으로 증명됨).
- **대안 풀이와의 트레이드오프**: 역방향으로 "i부터 끝까지 종류 수" 배열을 미리 채우면 제거 문제가 사라지지만 2패스 + 길이 N 배열이 든다. N=10^6에서 1패스 + O(K) 메모리가 낫다고 판단해 Counter 채택.
