### 2. EM 정규화 버그 수정 (U+2011)

`src/answer_eval.py` — `normalize_answer`의 문장부호 제거를 `string.punctuation`(ASCII 32자)에서 유니코드 일반 범주 `P*`/`S*` 판정으로 교체.

```python
- s = "".join(ch for ch in s if ch not in set(string.punctuation))
+ s = "".join(ch for ch in s
+             if not unicodedata.category(ch).startswith(("P", "S")))
```

모델이 U+2011(NON-BREAKING HYPHEN)을 출력하는데 걸러지지 않았다. 코드로 재확인:

| 문자 | category | NFKC 결과 | `string.punctuation` 포함 |
|---|---|---|---|
| U+2011 | `Pd` | → U+2010 | **False** |
| U+2010 | `Pd` | → U+2010 | **False** |
| U+002D | `Pd` | → U+002D | True |

★ NFKC가 U+2011을 U+2010으로 접기는 하는데 **ASCII 하이픈까지 가지 않는다.** 그래서 정규화를 통과하고도 하이픈이 남아 `jang hyun‑seung` ≠ `jang hyunseung`이 됐다. 정답인데 EM=0.

영향: 292건 중 4건 오답 처리. **Phase A 결과 포함 그동안의 모든 EM이 과소평가돼 있었다.**

## 배운 개념

- **"남은 손실은 생성에 있다"가 절반만 맞았다.** Agentic이 gold를 다 회수한 구간(n=40)에서도 Gold Context 0.725 vs Agentic 0.625로 **+0.100이 남는다.** 같은 gold 문서를 봤는데 결과가 다르면 차이는 함께 들어온 **방해 문서**다. 손실은 정밀도 13.5%p + 생성 35.1%p 두 몫으로 갈린다. recall은 목표를 달성했지만 **정밀도는 아니다** — 이건 이번 측정 전까지 못 보던 축이다.

- **소거법으로 지목한 병목은 직접 측정으로 갈라진다.** 기존 근거는 "recall 0.925인데 EM 0.350"이라는 간접 추론이었다. 통제 조건 두 개를 추가하니 같은 숫자가 두 개의 다른 원인으로 쪼개졌다. 소거법은 병목의 **위치**를 좁히지만 **개수**는 알려주지 않는다.

- **유니코드 문장부호는 코드포인트 열거로 못 잡는다.** ASCII 집합에 U+2011을 추가해도 U+2012, U+2013, U+2212가 남는다. 일반 범주(`Pd`, `P*`, `S*`)로 잡아야 뚫리지 않는다. NFKC를 걸었다고 안심한 게 함정이었다 — **NFKC는 호환 문자를 정규 문자로 접을 뿐 ASCII화하지 않는다.**

- **원본을 저장하고 파생값은 분석 시점에 계산한다.** 집계값(em/f1)을 JSONL에 저장한 것이 실수였다. 정규화를 고치면 저장값이 조용히 낡는다. 반대로 answer 원문을 저장한 덕에 292건 재채점이 API 호출 0회로 끝났다. **저장 시점에 계산한 값은 계산식이 바뀌면 거짓말이 된다.**

- **closed-domain 전제는 데이터셋 전체가 아니라 구간별로 성립한다.** HotpotQA를 closed-domain으로 뭉뚱그리면 comparison(No Context 0.615)에서 검색 효과를 심하게 과대평가한다. 유명 엔티티 비교는 검색이 쉬워서가 아니라 **애초에 덜 필요하다.**
