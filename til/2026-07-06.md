# 2026-07-06 TIL

## 오늘 한 것
- **`code/week12/agentic_rag.ipynb`** — Agentic RAG를 단발 tool calling에서 **ReAct(Reason+Act) 루프**로 확장. Groq SDK로 `search` 도구 등록(`retrieve_and_rerank`를 래핑해 상위 문서를 `"\n".join`으로 문자열화), 도구 스키마(`name`/`description`/`parameters`: `query` string) 정의, `run_agent(question, max_steps=5)` 다단계 루프 구현 — LLM이 `tool_calls`를 반환하면 내 코드가 실제 `search` 실행 → 결과를 `role:"tool"`(+`tool_call_id`)로 대화에 되돌려 다음 스텝 진행, `tool_calls`가 없으면 그 응답을 최종 답으로 반환. `system` 프롬프트로 (1) 답하기 전 반드시 검색, (2) 검색어는 한국어 강제, (3) 다주제 질문은 각각 따로 검색, (4) 검색 결과에 없으면 "자료에 없다"는 규칙 부과. `[step N] tool_calls / 검색어 / 결과 길이`를 print해 추론 과정을 눈으로 관찰.
- **`code/week12/rag_pipeline.py`** — 검색→재정렬→생성 파이프라인을 **import용 모듈**로 리팩터. `reranker`(`CrossEncoder("BAAI/bge-reranker-base")`)와 `vectorstore`를 import 시 1회 생성, `retrieve_and_rerank`(bi-encoder `first_k=20` 후보 → cross-encoder `top_k=3` 재정렬), `generate_answer`(근거 컨텍스트만으로 한국어 답), `rag_pipeline`(답+근거 반환)로 분리. 데모/테스트는 `if __name__ == "__main__"` 아래에만 둬 import 시 무거운 실행이 안 돌게 격리.
- **`code/week12/rag_app.py`** — 공용 문서셋(`TEXTS`)과 `build_vectorstore`(multilingual 임베딩 + Chroma), LCEL 체인(`make_rag_chain`)을 정리해 `rag_pipeline`이 그대로 재사용하도록 함. `TEXTS`는 near-miss(같은 키워드·다른 초점)와 far distractor(어텐션·토큰화)를 섞어 재정렬 효과가 드러나게 구성.

## 배운 개념
- **ReAct 루프 = tool calling의 `while` 확장.** 단발 tool calling(1왕복)과 달리 "도구 호출 → 결과 관찰 → 다시 판단"을 `max_steps`만큼 반복한다. LLM이 매 스텝 `tool_calls` 유무로 "더 검색할지 / 이제 답할지"를 스스로 분기하는 것이 에이전트의 핵심.
- **모듈 경계(import vs `__main__`).** import하면 정의(함수·객체)만 로드되고 `if __name__ == "__main__"` 블록은 실행되지 않는다 → 임베딩/모델 로드 같은 무거운 초기화를 데모에서 떼어낼 수 있다. 서빙에선 서버 시작 시 1회 로드해 재사용하므로 상단 초기화가 정당화된다.
- **시스템 프롬프트가 에이전트 행동을 규정한다.** "답 전 반드시 검색", "검색어 한국어", "다주제는 분리 검색", "근거 없으면 없다고"가 도구 사용 타이밍·검색 품질·환각 억제를 좌우. 도구 `description`은 LLM이 "언제 이 도구를 쓸지" 판단하는 근거.
- **2단계 검색을 도구로 캡슐화.** bi-encoder로 넓게 뽑고 cross-encoder로 정밀 재정렬하는 `retrieve_and_rerank`를 함수로 묶으니 에이전트의 `search` 도구가 그대로 재활용됐다.

## 막힌 부분
- **도구 결과를 대화에 되돌리는 형식.** `tool_calls`를 받은 뒤 assistant 메시지를 먼저 `append`하고, 각 결과를 `role:"tool"` + 대응하는 `tool_call_id`로 넣어야 다음 호출이 이어진다. 하나라도 누락되면 루프가 깨진다.
- **검색어 언어·분리.** 지식 베이스가 한국어라 LLM이 영어 검색어를 만들면 검색 품질이 떨어짐 → 시스템 프롬프트로 한국어·주제별 분리를 강제해 교정.
- **import 부작용 트레이드오프.** 모듈 상단에서 `vectorstore`(26개 임베딩)를 만들면 import가 느려지는 걸 인지 — 서빙에선 1회 로드라 감수하기로.
