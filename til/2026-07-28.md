## 배운 개념
- **GCD 후보 축소**: 조건1을 만족하는 `a`는 반드시 `A` 전부를 나누므로 `a ≤ gcd(A)`. "가장 큰 a"를 원하니 후보는 `gcd(A)`, `gcd(B)` 딱 두 개. `gcd(A)`가 실패하면 그 약수는 더 작고 위험만 크므로 볼 필요 없음 → 약수 나열·배수 순회 불필요.
- **"나눈다" ≠ "서로소가 아니다"**: `b % a == 0`(나눔)과 `gcd(a,b) == 1`(서로소)은 다른 관계. 반례 A=[4], B=[6] → 4는 6을 못 나누지만 `gcd(4,6)=2`. 공약수가 있어도 나누어떨어지지 않을 수 있음 → 직접 `all(b % gcdA != 0 for b in B)`로 검사.
- **reduce / 유클리드 호제법**: `reduce(gcd, arr)`는 리스트를 왼쪽부터 이항 연산으로 접어 하나로. 빈 리스트 방어는 초기값 `reduce(gcd, arr, 0)` (gcd에서 0은 항등원).
- **context_precision vs faithfulness**: precision은 "각 문서가 정답의 근거인가"(문서 기준, 검색 품질), faithfulness는 "답의 각 주장이 컨텍스트에 있나"(답 기준, 환각). 쓰레기 문서를 많이 긁으면 precision이 떨어져 "많이 긁기"에 벌점.
- **LLM judge 직접 구현**: 문서마다 yes/no 한 단어 강제 프롬프트 + 지수 백오프 재시도로 rate limit 방어. gold 라벨 문서는 judge에 안 맡기고 자동 relevant 처리.

## 막힌 부분
- **조건 방향 뒤집힘**: 초안이 `gcd(A)`가 A를 "안 나눔"을 검사 → gcd 정의상 항상 거짓이라 조건이 절대 성립 안 함. 검사할 건 "gcd(A)가 B를 안 나눔" 하나뿐.
- **덮어쓰기 vs 누적**: 초안이 조건 무시하고 `answer = max(gcda, gcdb)`로 무조건 반환 → 두 조건 다 실패해도 0이 안 나옴. `answer=0`에서 시작해 통과한 것만 `max`로 갱신해야 "없는 case"가 공짜로 처리됨.
- **elif → 독립 if**: 두 조건은 동시 성립 가능하므로 `elif` 아님. 후보는 0으로 미리 깔아 NameError 방지.
- **judge가 gold를 오판**: judge가 정답 근거 문서를 no로 잘못 판정하는 걸 육안 검수(idx=2 bridge)로 발견 → gold는 judge에 안 맡기고 라벨 신뢰로 전환.
- **RAGAS 0.4.x 불안정 + Groq 제약**: RAGAS API 개편·자료 부족으로 당일 안정화 불확실 → 직접 구현으로 선회(면접 방어: 도망이 아니라 통제를 위한 선택). `llama-3.3-70b` 단종 → `openai/gpt-oss-120b`로 교체.
