## 배운 개념
- **연속 부분합 + 양수 → 투포인터의 핵심은 '리셋'이 아니라 '왼쪽 한 개 빼기'**: 모든 원소가 양수면 윈도우를 넓히면 합↑·좁히면 합↓ (단조). 합 부족=오른쪽 확장, 합 초과=왼쪽 **축소(빼기)**. 초과 시 합을 0으로 리셋하고 시작점부터 다시 더하면 시작점마다 재탐색이라 `O(n²)`. '왼쪽 원소 하나만 빼기'로 바꿔야 두 포인터가 앞으로만 가서 `O(n)`
- **최단 + 최선두 동시 선택 = strict `<` 갱신**: 투포인터는 시작 인덱스가 커지는 순서로 후보를 만나므로, best를 strict `<` 로만 갱신하면 "더 짧을 때만 교체 → 같은 길이는 먼저 만난(앞선) 것 유지"가 공짜로 따라온다. `<=`나 `>`로 갱신하면 '앞선 것' 규칙이 깨짐
- **'가장 최근 것부터 재개' = LIFO = stack**: 멈춘 작업을 다시 꺼내는 순서가 "마지막에 멈춘 것부터"면 자료구조는 고민할 것 없이 stack. 문제의 동작 순서(LIFO/FIFO)를 읽으면 자료구조가 바로 결정된다 (FIFO였다면 queue)
- **시각 비교는 'hh:mm' 문자열 말고 분 단위 정수로**: `h*60+m`로 정규화하면 비교·뺄셈(여유 시간 계산)이 그냥 정수 연산이 됨. 이름/시작/소요는 **통째로 묶어서** 정렬해야 정렬 시 짝이 안 깨진다
- **경계 포함 여부는 부등호 한 글자로 결정**: "끝나는 시각 == 다음 시작 시각이면 끝난 것"은 `<=`, 개구간이라 못 맞히는 어제 미사일 문제는 `>=`(strict). 같은 '경계 처리' 계열 — 포함/불포함 한 글자가 정답을 가름

## 막힌 부분
- **'리셋' 방식의 TLE**: 처음엔 합 ≥ k일 때 `answer=0`으로 초기화하고 시작점을 한 칸 옮겨 다시 더하는 방식 → 시작점마다 재탐색이라 `O(n²)`, `n=10⁶`에서 TLE. '리셋 대신 왼쪽 빼기'를 떠올리는 데 시간이 걸림 (양수→단조→투포인터 연결이 아직 즉답이 안 됨)
- **루프 조기 종료로 마지막 윈도우 놓침**: `while right < len` 으로 짜니 right가 끝에 닿는 순간 루프가 죽어서, **'왼쪽만 줄이면 나오는 마지막 윈도우'** 를 놓침 (여기서 한참 헤맴). `while True` + "확장도 못 하고(right==끝) 아직 합이 부족할 때만 break"로 고쳐야 함 → right==끝이어도 '축소'로 찾을 윈도우가 남아 있을 수 있다는 게 핵심
- **off-by-one (윈도우 경계)**: `sequence[right]`를 더한 *뒤에* `right += 1` 하므로 현재 합의 윈도우는 `[left, right-1]`. `new_len = right-left`, `end = right-1` 로 -1 보정. 한 박자 어긋난 인덱스 정의를 머릿속에 명확히 고정해야 안 틀림
- **과제 진행: 남는 시간 연쇄 처리 누락 충동**: 한 과제를 일찍 끝내고 남는 시간에 멈춘 과제 **여러 개**가 연달아 끝날 수 있는데, `if` 한 번으로 처리하면 1개만 빠짐 → `while stopplan and available` 로 남는 시간이 0 될 때까지 연쇄. 못 끝내면 `남은 시간 - available` 만큼 깎아서 도로 push
