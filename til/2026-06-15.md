## 배운 개념
- **"순서대로 K개만" 제약 = 청크를 K개만 생성해서 해결**: 광물을 앞에서부터 5개씩 묶되, 실제 캐는 수 `K = min(곡괭이 수, 전체 청크)`만큼만 청크를 만들면 "앞에서 K개를 순서대로"가 자동으로 성립. 제약을 나중에 거르지 말고 **생성 단계에서 차단**하는 게 깔끔
- **비싼 자원에 좋은 도구 몰아주기 = 비용 기준 정렬 후 순차 배정**: 다이아가 많은 청크일수록 좋은 곡괭이를 쓸 때 절감 효과가 큼 → `(다이아, 철)` 내림차순 정렬 + 좋은 곡괭이부터 순서대로 배정이 최적. 교환 논증으로 정당화되는 전형적 그리디 패턴
- **올림 나눗셈은 `(n + d - 1) // d`**: 청크 수처럼 "딱 안 떨어지면 하나 더"가 필요할 때 `len//5 + 1`은 배수에서 +1 버그. `(len + 4) // 5`로 적어야 안전
- **최소 횟수 + 균일 비용 → BFS, 가중치 있으면 다익스트라**: 문제를 보면 "이동 비용이 다 같은가?"를 먼저 판단. 같으면 BFS의 첫 도달 = 최단. 리코쳇 로봇은 "한 번 미끄러짐 = 비용 1"이라 BFS가 정답
- **상태(노드) 정의가 BFS의 절반**: 말의 위치만 상태로 잡고 방향은 이웃 계산에만 사용 → `visited`도 위치 기준이면 충분. 슬라이드 그래프엔 왔다갔다 사이클이 있어 `visited`가 필수
- **목표 칸의 "통과 가능 여부"가 도달 판정 위치를 바꾼다**: G가 멈춤 조건이 아니면(통과) 중간 칸에서 도착으로 오판하면 안 됨 → 도달 체크는 **정지 지점에서만**. 내부가 뚫린 칸의 G는 멈출 수 없어 도달 불가(-1)가 정답
