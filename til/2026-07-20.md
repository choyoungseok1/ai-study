## 오늘 한 것
- `code/week14/defense_game.py` — 프로그래머스 Lv2 "디펜스 게임" (min heap 그리디)
  - 라운드를 순회하며 `enemy[i]`를 일단 heap에 push = "무적권으로 막았다고 가정"
  - `len(heap) > k`가 되면 heap에서 최솟값을 pop 해 `n`에서 차감 = 병사로 되돌림
  - 결과적으로 무적권은 큰 값들에만 남아 병사 소모 최소화
  - 종료 판정 `n < 0` → `return i` (0-indexed라 i개 방어 성공)
  - 복잡도 O(len(enemy)·log k) ≈ 10^6 · log(5e5) ≈ 2천만 → 통과
  - 반례 검증 케이스 포함: `solution(3, 1, [1,1,1,1,4])` → 5

## 배운 개념
- **그리디의 "미리 확정" 함정**: 큰 값을 미리 골라 무적권을 배정하는 방식은 틀림.
  반례 `n=3, k=1, enemy=[1,1,1,1,4]` — 4에 무적권을 예약하면 앞의 1,1,1을 막다
  병사가 0이 되고 네 번째 1에서 죽어 4에 도달조차 못 함.
  → 미래를 확정하지 말고 **진행하면서 되돌리는(pop) 구조**로 바꾸면 최적이 된다.
- **연산 → 자료구조 매핑**: "최솟값/최댓값을 반복해서 꺼낸다", "top k를 유지한다",
  "우선순위" 이 세 신호 중 하나라도 보이면 heap. 이번엔 "무적권으로 막은 것 중
  가장 작은 값을 계속 꺼낸다"가 정확히 첫 번째 신호였다.
- **heap으로 top-k 유지하기**: 크기를 k로 제한한 min heap에 계속 push하고
  넘칠 때마다 pop하면, heap에는 항상 "가장 큰 k개"가 남는다.

## 막힌 부분
- **자료구조 선택이 느렸다.** "최솟값 반복 추출"이라는 요구가 문제에 그대로
  드러나 있었는데 스택 → deque를 먼저 짚고 heap에 늦게 도달. 지식 공백이 아니라
  연산→자료구조 매핑이 아직 반사적이지 않은 것. 위의 heap 신호 3종을 암기 대상으로.
- **`<` vs `<=` 재발.** 종료 조건을 `n <= enemy[i]`로 잡았는데, 병사 수와 적 수가
  같으면 막을 수 있으므로 틀림. 판정은 `n < 0`이 맞다 (`n <= 0` 아님 — 병사 0명은
  아직 죽은 게 아님). 반복 실수 목록에 이미 있던 항목이 또 나왔다.
  → 경계는 항상 구체적 숫자 두 개(3 vs 3, 3 vs 4)를 대입해 확인할 것.
- **들여쓰기 / 판정 위치.** `n < 0` 체크를 `len(heap) > k` 블록 **밖**에 뒀었다.
  답은 우연히 맞지만(n이 안 바뀌면 여전히 ≥ 0) 원인(n 감소)과 결과(사망 판정)가
  분리된 구조. → 판정은 값이 바뀐 자리에 붙인다.
