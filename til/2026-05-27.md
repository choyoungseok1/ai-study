  - 핵심 아이디어: 와일드카드(-)를 데이터 구축 시점에 combinations로 미리 처리 → 정렬 → bisect_left로 O(log n) 쿼리

## 배운 개념
- **BatchNormalization**: 각 레이어 출력을 정규화해서 학습 안정화. Conv2d 뒤에 BatchNorm2d 배치
- **Dropout**: 학습 시 노드를 랜덤으로 꺼서 과적합 방지. `model.eval()` 시 자동 비활성화
- **Data Augmentation**: RandomRotation, RandomAffine 등으로 훈련 데이터 다양성 확보. 항상 정확도가 오르진 않음 (99.25% → 99.00%)
- **LSTM 텍스트 분류 파이프라인**: vocab 구축 → 정수 인코딩 → 패딩 → Embedding → LSTM → hidden state로 분류
- **이진탐색 실전 패턴**: "미리 분류 + 정렬 → 쿼리 시 bisect_left"가 대량 쿼리 처리의 핵심
- **DP 기초**: 피보나치 구조 점화식, 큰 수 문제에서 매 단계 MOD 연산 필수

## 막힌 부분
- **bisect_left 적용 실수**: 순위검색 문제에서 bisect_left의 입력(정렬된 리스트)과 출력(삽입 위치)을 정확히 이해하지 못한 채 사용 → 라이브러리 쓸 때 입출력 스펙 먼저 확인하는 습관 필요
- **for문 내 결과 처리 실수**: 매 반복마다 append해야 하는데 for문 밖에서 마지막 값만 사용한 패턴 반복 → return/append 위치 체크리스트화
- **DP 접근 전 완전탐색 시도**: n=60,000인데 BFS/트리로 접근 → 제한 조건(n 크기)부터 확인하고 알고리즘 선택하는 습관 필요
- **Data Augmentation이 항상 성능 향상은 아님**: BatchNorm+Dropout(99.25%) > 증강 추가(99.00%). 데이터가 이미 충분하거나 증강이 과하면 오히려 성능 저하 가능
