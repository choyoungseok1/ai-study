  - 제한 `r2 ≤ 10⁶` → bounding box 전수조사는 `O(r2²) ≈ 10¹²` 로 TLE. `O(r2)` 풀이가 필요

  - 한 열의 개수 = `isqrt(r2²-x²) − isqrt(max(0, r1²-x²-1))` → 바깥 x 루프 하나만 남아 `O(r2)`
- 개념 정리: **파인튜닝** (vs RAG 언제 뭐 쓰나, LoRA / QLoRA) — Notion 6/9 항목

## 배운 개념
- **대칭으로 ×k 해서 격자점 세기**: 원·범위처럼 대칭이 있는 도형은 한 영역만 세고 회전 대칭만큼 곱한다. 여기선 `x≥0, y≥1` + ×4 가 `x≥1, y≥1` + 별도 축 보정항보다 깔끔 — 90° 회전 4번이 원점 빼고 평면을 정확히 1번씩 덮어서 축 보정이 자동으로 됨
- **"범위 안 개수 = (위 경계까지) − (아래 경계 미만)" (prefix 빼기)**: 한 열의 y 개수를 루프로 세지 말고 `isqrt(위) − isqrt(아래 미만)` 한 줄로. 어제 미사일 문제의 `[0,end] − [0,start]` 와 똑같은 무기 → 안쪽 루프 자체를 제거해 `O(r2²)→O(r2)`
- **`math.isqrt` 필수, `math.sqrt(float)` 금지**: `r2²=10¹²` 스케일에선 부동소수 정밀도가 깨져 경계가 1 틀어진다. 정수 제곱근이 필요하면 항상 `math.isqrt` (off-by-one 안전)
- **값 범위 ≠ 연산 횟수 (재확인)**: 좌표가 `10⁶`이어도 복잡도는 좌표축을 훑는 게 아니라 '입력/열 개수'에 달렸다. 큰 좌표값에 겁먹고 좌표 압축으로 갈 필요 없음 (미사일 문제에서 배운 것 반복 적용)
- **파인튜닝 vs RAG — '지식을 어디에 넣느냐'의 차이**: RAG는 외부 지식을 검색해 프롬프트 컨텍스트에 끼워 넣음(가중치 불변), 파인튜닝은 가중치 자체를 갱신해 지식·행동을 모델에 내재화. 자주 바뀌는 사실 / 출처 추적 / 적은 비용으로 최신화 → RAG, 말투·출력 형식·도메인 스타일처럼 일관된 행동을 박아 넣기 → 파인튜닝. 둘은 배타가 아니라 보완(파인튜닝 + RAG 병행 가능)
- **LoRA / QLoRA — 적은 자원으로 파인튜닝**: LoRA는 원본 가중치 `W`를 동결하고 저랭크 행렬 곱 `B·A`(= ΔW)만 학습 → 학습 파라미터 수가 급감. QLoRA는 베이스 모델을 4bit로 양자화해 메모리까지 줄여 단일 GPU(Colab 무료 등)에서도 큰 모델 파인튜닝이 가능

## 막힌 부분
- **`O(r2²)` 이중 루프 충동**: 처음엔 bounding box 전수조사로 감 → `r2=2000`에 이미 2.8초. "제한부터 보고 복잡도 먼저 정하기"가 아직 손에 안 붙음. 안쪽 루프를 `isqrt` 카운트로 갈아끼워야 한다는 걸 늦게 떠올림
- **`math.sqrt` 정밀도 함정**: float sqrt로 경계 개수가 1 틀어져 예제가 빗나감 → `math.isqrt`로 교체하고 나서야 통과. (배운 개념의 'isqrt 필수'를 직접 깨지고 배움)
- **`isqrt` 음수 입력**: 아래 경계 `r1²-x²-1` 이 음수가 되는 열에서 `isqrt(음수)` 터짐 → `max(0, …)` 클램프로 방어. 위 경계 `r2²-x²` 는 `x ≤ r2` 라 항상 ≥0이라 클램프 불필요(왜 한쪽만 클램프하는지까지 정리)
- **대칭 영역 선택을 한참 헤맴**: `x≥1, y≥1`로 잡으면 축 위의 점을 따로 더해야 해서 식이 지저분 → `x≥0, y≥1` + ×4 로 바꾸니 축 보정이 자동. '어떤 기본 영역이 중복·누락 없이 ×k 되는가'를 먼저 정하는 게 핵심
