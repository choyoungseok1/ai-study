# 2026-07-07 TIL

## 오늘 한 것
- **`code/week12/serve.py`** — 어제 모듈화한 `rag_pipeline`을 **FastAPI로 감싸 HTTP API로 서빙**. `from rag_pipeline import rag_pipeline`로 파이프라인을 그대로 재사용하고, `FastAPI()` 앱에 `POST /ask` 엔드포인트 하나를 정의. 요청 스키마는 Week 11에서 쓰던 Pydantic을 재활용해 `AskRequest(question: str)`로 받고, 핸들러에서 `answer, sources = rag_pipeline(req.question)`을 호출해 `{"answer": answer, "sources": sources}` JSON으로 반환. 검색→재정렬→생성 로직은 손대지 않고 "입출력 경계"만 얹은 얇은 서빙 레이어 구현.

## 배운 개념
- **서빙 = 파이프라인 로직 위에 얇은 입출력 레이어.** 핵심 로직(`rag_pipeline`)은 그대로 두고, "요청을 받아 함수를 호출하고 결과를 직렬화해 돌려주는" 부분만 FastAPI가 담당한다. 로직과 전송(transport)을 분리하니 CLI/노트북/서버 어디서든 같은 함수를 재사용할 수 있다.
- **Pydantic 요청 스키마(`BaseModel`).** `AskRequest(question: str)`를 선언하면 FastAPI가 요청 body를 자동 검증·파싱해준다. Week 11에서 배운 Pydantic이 그대로 API 입력 계약(contract)으로 이어짐.
- **모듈 import가 서빙의 전제.** 어제 `if __name__ == "__main__"`으로 무거운 초기화를 격리해둔 덕분에, `serve.py`가 `rag_pipeline`을 import해도 데모가 안 돌고 정의만 로드된다. 서버 시작 시 `vectorstore`/`reranker`가 1회만 올라가고 이후 요청은 재사용 → 서빙 패턴이 정당화됨.
- **엔드포인트 설계의 기본형.** `@app.post("/ask")` + 요청 모델 + 응답 dict. 답(`answer`)과 근거(`sources`)를 함께 돌려줘, 클라이언트가 출처까지 확인할 수 있게 함.

## 막힌 부분
- **import 시점의 무거운 초기화.** `rag_pipeline`을 import하는 순간 임베딩 벡터스토어와 cross-encoder가 로드돼 서버 첫 기동이 느려진다. 서빙에선 "시작 시 1회 로드 후 재사용"이라 감수하지만, 요청마다 다시 안 만들도록 전역 1회 로드 구조를 지키는 게 중요.
- **`sources` 원문 그대로 반환.** 근거 문서 텍스트를 통째로 응답에 실으면 지식베이스 내용이 그대로 노출된다. 실제 서비스면 제목/스니펫만 주거나 접근 제어가 필요 — 지금은 학습용이라 원문 반환.
- **아직 없는 것들.** 예외 처리(빈 질문·모델 오류), 동시 요청 처리, 응답 스키마(Pydantic response_model) 미정의. "맛보기" 수준이라 다음에 보강 여지.
