## 1. Don't Waste Bits! Adaptive KV-Cache Quantization for Lightweight On-Device LLMs

**arxiv**: [https://arxiv.org/abs/2604.04722](https://arxiv.org/abs/2604.04722)
**발표일**: 2026년 4월 6일 (CVPR 2026 채택)
**코드**: 논문 내 알고리즘 상세 공개 (공식 리포 확인 필요)
**페이지**: 약 10페이지

### 초록 요약
온디바이스 LLM 추론에서 KV 캐시의 메모리·대역폭 오버헤드가 병목이 되는 문제를 해결하기 위해, 토큰별 중요도에 따라 {2-bit, 4-bit, 8-bit, FP16} 중 최적 정밀도를 동적으로 선택하는 경량 컨트롤러를 제안한다. 기존의 고정 정밀도·수작업 휴리스틱 방식 대비, SmolLM-360M에서 디코딩 지연시간 17.75% 감소 + HellaSwag 정확도 7.60점 향상을 달성하면서 FP16 대비 0.30점 차이에 불과하다.

### 추천 이유
1. 이번 주 Transformer 리뷰에서 KV Cache → GQA → MLA까지 정리한 흐름의 자연스러운 다음 단계로, "캐시를 어떻게 압축하는가"에 대한 실전 최적화 기법을 배울 수 있다.
2. CVPR 2026 채택 논문으로 검증된 품질이며, 온디바이스 추론이라는 실용적 주제가 ML 엔지니어 취업 면접에서 자주 등장하는 토픽이다.
3. 2-bit부터 FP16까지 적응적으로 선택하는 구조가 직관적이어서, 양자화 개념을 처음 접하는 단계에서도 핵심 아이디어를 파악하기 좋다.

## 2. Drawing Pandas: A Benchmark for LLMs in Generating Plotting Code

**arxiv**: [https://arxiv.org/abs/2412.02764](https://arxiv.org/abs/2412.02764)
**발표일**: 2024년 12월 3일 (v2: 2025년 2월 26일)
**코드**: [https://github.com/JetBrains-Research/PandasPlotBench](https://github.com/JetBrains-Research/PandasPlotBench)
**페이지**: 약 12페이지

### 초록 요약
LLM이 자연어 지시문에서 데이터 시각화 코드를 얼마나 잘 생성하는지 평가하기 위한 벤치마크 "PandasPlotBench"를 제안한다. 175개 고유 태스크를 설계하고, Matplotlib·Seaborn·Plotly 세 라이브러리에 대해 주요 LLM들의 코드 생성 능력을 체계적으로 평가한다. Matplotlib과 Seaborn에서는 높은 성능을 보이지만 Plotly에서는 여전히 한계가 있으며, 간결한 프롬프트로도 성능 저하가 미미함을 확인한다.

### 추천 이유
1. 이번 주 Matplotlib + Seaborn을 막 배운 시점에서, "LLM이 같은 도구로 어떤 코드를 생성하는지" 관점으로 읽으면 본인의 코딩과 비교하며 학습 효과가 극대화된다.
2. 코드가 GitHub에 공개되어 있어 PandasPlotBench를 직접 돌려보면서 시각화 실력과 LLM 활용 감각을 동시에 키울 수 있다.
3. "LLM + 시각화" 교차점은 데이터 분석 직무에서 점점 중요해지는 주제로, 포트폴리오에 벤치마크 재현 실험을 넣으면 차별화된다.

## 3. Latent-Condensed Transformer for Efficient Long Context Modeling

**arxiv**: [https://arxiv.org/abs/2604.12452](https://arxiv.org/abs/2604.12452)
**발표일**: 2026년 4월 17일
**코드**: 논문 내 알고리즘 상세 공개 (공식 리포 확인 필요)
**페이지**: 약 14페이지

### 초록 요약
Multi-head Latent Attention(MLA)의 잠재 공간 내에서 직접 컨텍스트를 압축하는 Latent-Condensed Attention(LCA)을 제안한다. 의미 벡터는 query-aware pooling으로 집약하고, 위치 키는 앵커 선택으로 보존하여 연산 비용과 KV 캐시를 동시에 줄인다. 추가 파라미터 없이 MLA에 적용 가능하며, GQA 등 다른 어텐션 메커니즘에도 아키텍처-무관하게 확장된다.

### 추천 이유
1. Transformer 리뷰에서 MLA(Multi-Latent Attention)를 정리한 직후이므로, MLA 위에서 "어떻게 더 최적화하는가"의 최전선 연구를 바로 이어서 읽을 수 있다.
2. GQA → MLA → LCA로 이어지는 어텐션 최적화의 계보를 한 눈에 볼 수 있어, 면접에서 "효율적 어텐션의 발전사"를 설명할 때 완결성이 높아진다.
3. 2026년 4월 최신 논문이며, 추가 파라미터 없이 성능을 개선한다는 실용적 메시지가 리소스 제한 환경의 ML 엔지니어에게 특히 와닿는다.

## 4. PlotGen: Multi-Agent LLM-based Scientific Data Visualization via Multimodal Feedback

**arxiv**: [https://arxiv.org/abs/2502.00988](https://arxiv.org/abs/2502.00988)
**발표일**: 2025년 2월 3일
**코드**: 논문 내 프레임워크 상세 공개 (공식 리포 확인 필요)
**페이지**: 약 13페이지

### 초록 요약
과학 데이터 시각화를 자동화하는 멀티 에이전트 프레임워크 "PlotGen"을 제안한다. Query Planning Agent가 복잡한 사용자 요청을 분해하고, Code Generation Agent가 Python 코드를 생성하며, Numeric/Lexical/Visual 세 가지 피드백 에이전트가 멀티모달 LLM을 활용해 데이터 정확도·텍스트 레이블·시각적 올바름을 반복적으로 개선한다. 기존 단일 에이전트 방식 대비 정확도와 시각 품질 모두에서 유의미한 개선을 보인다.

### 추천 이유
1. Matplotlib/Seaborn을 직접 코딩하는 경험과 "LLM이 같은 일을 멀티 에이전트로 자동화하는 방식"을 대비하면, 수동 vs 자동의 갭을 체감하며 향후 도구 활용 방향을 그릴 수 있다.
2. 멀티 에이전트 아키텍처(Planning → Generation → Feedback 루프)는 LLM 응용 엔지니어가 반드시 이해해야 할 설계 패턴이다.
3. 지난주 추천한 ToolMaker(에이전트 도구 생성)와 자연스럽게 연결되며, "에이전트가 시각화까지 한다"는 한 단계 발전된 시야를 제공한다.
