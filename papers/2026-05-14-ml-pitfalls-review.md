## 섹션별 정리

### 2. 모델 구축 전 주의사항 (Before you start to build models)

1. **데이터 사용 방법과 장소 고민하기**: 훈련, 검증, 테스트 데이터의 역할을 명확히 구분하고, 특히 검증 세트가 여러 번의 비교 과정에서 오염될 수 있음을 인지해야 함.

2. **데이터 이해에 시간 투자하기**: 데이터의 출처와 품질을 확인해야 하며, 단순히 많이 쓰이는 데이터셋이라고 해서 품질이 좋을 것이라 맹신해서는 안 됨 ('Garbage In, Garbage Out').

3. **모든 데이터를 다 보지 않기**: 초기 분석 단계에서 테스트 데이터를 자세히 들여다보면 모델의 범용성을 해치는 테스트 불가능한 가정을 하게 될 수 있음.

4. **데이터 정제(Cleaning)**: 중복 데이터 제거, 결측치 처리(임퓨테이션), 이상치(outlier) 확인 등을 모델 구축 전에 완료해야 함.

5. **충분한 데이터 확보 확인**: 데이터가 부족하면 증강(Augmentation)이나 전이 학습(Transfer Learning)을 고려하되, 데이터 분할 전 증강을 하는 등의 실수를 피해야 함.

6. **도메인 전문가와 상담**: 전문가의 조언은 유용한 문제 정의와 적절한 피처(Feature) 선정에 큰 도움이 됨.

7. **문헌 조사 수행**: 기존 연구를 통해 이미 실패한 접근법을 피하거나, 자신의 연구를 정당화할 근거를 마련해야 함.

8. **모델 배포 환경 고려**: 실제 환경에서 사용될 모델이라면 자원 제한, 시간 제약, 에너지 비용 등을 미리 고려해야 함.

### 3. 신뢰할 수 있는 모델 구축 (How to reliably build models)

1. **테스트 데이터 유출 금지**: 테스트 데이터의 정보가 모델 구성, 훈련, 피처 선택 과정에 스며들지 않도록 엄격히 관리해야 함 (Data Leakage 방지). StandardScaler를 train에만 fit하는 이유가 바로 이것.

2. **다양한 모델 시도**: 모든 문제에 완벽한 단일 모델은 없으므로(No Free Lunch), 여러 모델을 시도하여 최적의 조합을 찾아야 함.

3. **부적절한 모델 사용 금지**: 범주형 피처에 수치형 모델을 적용하는 등의 데이터 특성에 맞지 않는 모델 선택을 피해야 함.

4. **딥러닝 발전 및 함정 파악**: 딥러닝을 사용할 경우 최신 기술 트렌드와 함께 해당 모델들이 가진 데이터 요구량 등 고유의 한계를 이해해야 함.

5. **딥러닝이 항상 최선이라는 착각 버리기**: 문제에 따라 고전적인 머신러닝 기법이 더 효율적이고 성능이 좋을 수 있음. 테이블 데이터에서는 트리 기반 모델이 딥러닝보다 강할 수 있다.

6. **피처 선택 시 주의**: 데이터 분할 전 피처를 선택하면 정보 유출이 발생. 피처 선택/PCA는 반드시 데이터 분할 후 train에서만 수행해야 함.

7. **하이퍼파라미터 최적화**: 모델 간의 공정한 비교를 위해 각 모델의 하이퍼파라미터를 충분히 최적화해야 함. Grid search, random search 등 활용.

8. **가짜 상관관계(Spurious Correlations) 주의**: 모델이 실제 인과관계가 아닌 데이터의 노이즈나 우연한 패턴을 학습하지 않는지 경계해야 함 (탱크 문제 사례).

---

### 4. 견고한 모델 평가 (How to robustly evaluate models)

1. **적절한 테스트셋 사용**: 훈련셋과 겹치지 않고 모집단을 대표할 수 있는 독립적인 테스트셋을 사용해야 함.

2. **데이터 분할 전 증강 금지**: 데이터 증강(Augmentation)은 반드시 데이터를 나눈 후 '훈련셋'에만 적용해야 함.

3. **순차적 과적합(Sequential Overfitting) 방지**: 동일한 테스트셋을 반복적으로 사용해 모델을 수정하면 결국 테스트셋에 과적합됨. validation set을 분리하는 이유.

4. **다회 평가 수행**: 단 한 번의 실험 결과가 아닌, 교차 검증 등을 통해 여러 번 평가하여 결과의 안정성을 확인해야 함.

5. **최종 모델 인스턴스 평가 데이터 보존**: 모든 튜닝이 끝난 후 최종 성능 확인을 위한 데이터를 따로 남겨두어야 함.

6. **평가지표 선택**: 데이터 불균형 시 정확도(Accuracy)는 기만적일 수 있으므로 F1 스코어, MCC 등 적절한 지표를 써야 함.

7. **모델 공정성(Fairness) 고려**: 성능 지표 외에도 성별, 인종 등에 따라 모델이 불평등한 결과를 내놓지 않는지 확인해야 함.

8. **시계열 데이터의 시간적 의존성 존중**: 시계열 데이터를 랜덤하게 섞어서 나누면 미래의 정보가 과거로 유출됨 (look ahead bias).

## 새로 알게 된 것

### 혼공머신러닝과 연결되는 개념
- **Data Leakage**가 단순 실수가 아니라 ML 모델 실패의 핵심 원인. StandardScaler를 train에만 fit하고 test엔 transform만 하는 이유가 여기서 나옴
- **Sequential Overfitting**: 같은 테스트셋으로 반복 평가하면 테스트셋에 과적합됨. `cross_validate`에서 validation set과 test set을 분리하는 이유
- **불균형 데이터에서 Accuracy는 기만적**. numpy로 손구현한 MSE, R²도 회귀에서 RMSE만 보면 "변화 없음 예측"이 좋아 보일 수 있음

### ML 전반에 대한 인사이트
- **No Free Lunch 정리**: 모든 문제에 최고인 단일 모델은 없다. 여러 모델 시도가 필수
- **피처 선택/PCA도 반드시 데이터 분할 후 train에서만 해야 함**
- **딥러닝이 항상 최선이 아님**. 테이블 데이터에서는 트리 기반 모델이 더 강할 수 있음
- **시계열 데이터는 랜덤 분할하면 미래 정보가 유출됨** (look ahead bias)
- **가짜 상관관계(Spurious Correlations)**: 탱크 문제처럼 모델이 배경 색상으로 분류하는 실수
