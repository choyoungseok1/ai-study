## 1. HiRA — Parameter-Efficient Hadamard High-Rank Adaptation (ICLR 2025, Oral) ⭐ PEFT

**초록 요약**
LoRA의 저랭크(low-rank) 업데이트는 파라미터는 적지만 새로운 태스크에 대한 *표현력*이 제한된다는 한계가 있다. HiRA는 사전학습 가중치 W₀에 LoRA 모듈(BA)을 **아다마르 곱(Hadamard product)** 으로 결합해 `ΔW = W₀ ⊙ (BA)` 형태의 **고랭크(high-rank) 업데이트**를 만든다. 파라미터 수는 LoRA 수준으로 유지하면서 모델 업데이트의 유효 랭크를 끌어올리고, 사전학습 가중치에 병합되어 **추론 오버헤드가 0**이다. commonsense reasoning, 대화 생성, 수학 추론 등에서 LoRA 및 그 변형들을 능가한다.

**추천 이유 (3줄)**
- 지난주 읽은 **DoRA의 자연스러운 다음 단계** — "LoRA의 표현력 한계를 어떻게 깰까"라는 같은 문제의식을 다른 방식(아다마르 곱)으로 푼다.
- **ICLR 2025 Oral** 채택작이라 PEFT 최신 흐름을 정확히 짚기 좋고, 수식이 간결해 입문 후 단계로 적당하다.
- 공식 **코드 공개**되어 바로 LoRA ↔ DoRA ↔ HiRA 비교 실험을 돌려볼 수 있다.

**링크**
- 논문(OpenReview, ICLR 2025): https://openreview.net/forum?id=TwJrTz9cRS
- 코드: https://github.com/hqsiswiliam/hira
- 한글 참고(PEFT/DoRA 맥락): [DoRA 한글 정리 — PyTorchKR](https://discuss.pytorch.kr/t/dora-lora-weight-decomposed-low-rank-adaptation/3528) · [NVIDIA Developer KR — DoRA 살펴보기](https://forums.developer.nvidia.com/t/lora-dora/305089)

*분량: ICLR 본문 ~10p (부록 별도)*

## 2. LightRAG — Simple and Fast Retrieval-Augmented Generation (EMNLP 2025) ⭐ RAG 입문

**초록 요약**
기존 RAG는 (1) 평면적(flat) 데이터 표현과 (2) 문맥 인식 부족으로 복잡한 질의에서 한계를 보인다. LightRAG는 **지식 그래프(knowledge graph) 구조를 텍스트 인덱싱·검색 과정에 통합**하고, 저수준(구체적 사실)과 고수준(추상적 개념)을 동시에 가져오는 **이중 검색(dual-level retrieval)** 구조를 쓴다. GraphRAG의 무거운 커뮤니티 요약 전처리 없이 엔티티-관계 추출 + 벡터 검색 하이브리드로 LLM 호출 수와 응답 지연을 크게 줄이고, **증분 업데이트(incremental update)** 로 새 데이터를 빠르게 반영한다.

**추천 이유 (3줄)**
- **목표(LLM 응용)에 가장 직접적인 RAG 핵심 프레임워크** — vector RAG와 graph RAG 사이를 잇는 실무 표준급 방법이다.
- GitHub 스타가 매우 많은 인기 레포라 **돌려보며 익히기 좋고**, EMNLP 2025 정식 채택작이라 신뢰도가 높다.
- **한글 해설 블로그가 풍부**해 개념 잡기 쉽다(아래 링크).

**링크**
- arXiv: https://arxiv.org/abs/2410.05779
- 코드: https://github.com/HKUDS/LightRAG
- 한글 해설: [PyTorchKR 정리](https://discuss.pytorch.kr/t/lightrag-graphrag-rag-feat-emnlp-2025/9612) · [박재홍의 실리콘밸리(위키독스)](https://wikidocs.net/blog/@jaehong/11397/) · [velog 논문 정리](https://velog.io/@hansoljang/LIGHTRAG-SIMPLE-AND-FAST-RETRIEVAL-AUGMENTED-GENERATION)

*분량: 본문 ~13p 내외(15p 목표 부합)*

## 3. A-RAG — Scaling Agentic RAG via Hierarchical Retrieval Interfaces (arXiv, 2026-02) 🆕 최신·도전

**초록 요약**
최신 LLM은 강력한 추론·도구 사용 능력을 갖췄지만, 기존 RAG는 (1) 한 번에 검색해 입력에 붙이거나 (2) 사전 정의된 워크플로를 단계별로 실행하는 방식이라 **모델이 검색 결정에 직접 참여하지 못한다**. A-RAG는 에이전트에게 **계층적 검색 인터페이스(keyword search / semantic search / chunk read) 세 가지 도구를 직접 노출**해, 모델이 여러 granularity로 적응적으로 검색하게 한다. 여러 open-domain QA 벤치마크에서 더 적거나 비슷한 검색 토큰으로 기존 방법을 일관되게 능가하며, 모델 크기·test-time compute에 따른 스케일링도 분석한다.

**추천 이유 (3줄)**
- **가장 최신(2026-02) "에이전트형 RAG"** 흐름 — LightRAG로 RAG 기초를 잡은 뒤 보면 "다음 세대"가 보인다.
- 코드 + **평가 스위트까지 공개**라 벤치마크 재현·실험에 유리하다.
- 단, **18페이지로 15p 목표를 약간 초과** → 시간 부족하면 §방법론·실험만 발췌해 읽기를 추천.

**링크**
- arXiv: https://arxiv.org/abs/2602.03442
- 코드: https://github.com/Ayanami0730/arag

*분량: 18p (목표 초과, ⚠️ 발췌 읽기 권장)*
