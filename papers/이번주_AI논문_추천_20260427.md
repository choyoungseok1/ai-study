## 1. Beyond BeautifulSoup: Benchmarking LLM-Powered Web Scraping for Everyday Users

**arxiv**: [https://arxiv.org/abs/2601.06301](https://arxiv.org/abs/2601.06301)
**발표일**: 2026년 1월 9일
**코드**: 없음 (벤치마크 중심, 단 논문 내 코드 예시 풍부)
**페이지**: 약 12페이지

### 초록 요약
LLM이 웹 스크래핑을 민주화했다는 전제 하에, 일반 사용자가 기존 도구(Scrapy, BeautifulSoup)와 LLM 기반 도구(Claude, Simular.ai 등)를 사용해 35개 사이트(인증·안티봇·CAPTCHA 5단계 보안 포함)에서 스크래핑하는 성능을 체계적으로 벤치마크한 논문. (a) LLM 보조 스크립팅과 (b) 엔드투엔드 LLM 에이전트 두 워크플로우를 비교한다.

### 추천 이유
1. 지금 막 BeautifulSoup을 배우고 있는 시점에 "전통적 크롤링 vs LLM 크롤링"의 차이를 조감할 수 있어, 학습 동기와 방향 감각을 동시에 잡아준다.
2. 논문 제목 자체가 "Beyond BeautifulSoup"이라 현재 공부 중인 도구가 업계에서 어떤 위치인지 맥락을 이해하기 좋다.
3. 프롬프트 한 줄로 복잡한 스크래핑을 완료하는 사례가 포함되어, LLM 응용 엔지니어로서의 미래 업무를 구체적으로 그려볼 수 있다.

## 2. LLM Agents Making Agent Tools (ToolMaker)

**arxiv**: [https://arxiv.org/abs/2502.11705](https://arxiv.org/abs/2502.11705)
**발표일**: 2025년 2월 (ACL 2025 채택)
**코드**: ✅ [https://github.com/KatherLab/ToolMaker](https://github.com/KatherLab/ToolMaker)
**페이지**: 약 10페이지

### 초록 요약
GitHub URL과 짧은 태스크 설명만 주면, LLM 에이전트가 자동으로 의존성을 설치하고 해당 리포지토리를 LLM 호환 도구로 변환하는 프레임워크 "ToolMaker"를 제안. 폐쇄 루프 자기 수정 메커니즘으로 디버깅하며, 15개 복합 태스크 × 100+ 유닛 테스트 벤치마크에서 80% 성공률로 기존 소프트웨어 엔지니어링 에이전트를 크게 상회했다.

### 추천 이유
1. 지난주 추천한 Paper2Code의 자연스러운 후속 논문으로, "논문→코드"를 넘어 "코드→도구"까지 자동화하는 파이프라인을 보여준다.
2. GitHub 리포를 도구로 바꾸는 과정이 requests/BeautifulSoup으로 데이터를 수집→가공하는 흐름과 개념적으로 유사해, 지금 배우는 것과 연결짓기 좋다.
3. ACL 2025 채택 논문으로 검증된 품질이고, 코드가 공개되어 직접 실행해볼 수 있다.

## 3. Lightweight LLM Agent Memory with Small Language Models (LightMem)

**arxiv**: [https://arxiv.org/abs/2604.07798](https://arxiv.org/abs/2604.07798)
**발표일**: 2026년 4월 9일 (v3: 4월 22일)
**코드**: 논문 내 알고리즘 공개 (공식 리포 확인 필요)
**페이지**: 약 12페이지

### 초록 요약
LLM 에이전트의 메모리 시스템을 Small Language Model(SLM)로 경량화한 "LightMem" 제안. 단기 기억(STM), 중기 기억(MTM), 장기 기억(LTM)으로 계층화하고, 온라인 처리와 오프라인 통합을 분리하여 지연시간을 줄이면서 정확도를 유지한다. 검색 기반 외부 메모리의 불안정한 정확도와, 대형 모델 반복 호출의 높은 지연시간 문제를 동시에 해결한다.

### 추천 이유
1. 2026년 4월 최신 논문으로, LLM 에이전트의 "기억" 문제를 다루며 — RAG(지난주 추천)와 자연스럽게 이어지는 주제다.
2. STM/MTM/LTM 3단계 구조는 사람의 기억 체계와 비슷해 직관적으로 이해하기 좋고, 면접에서 "에이전트 메모리 설계"를 설명할 때 유용하다.
3. "작은 모델로도 충분하다"는 메시지는 GPU 자원이 제한된 개인 학습자에게 실용적인 영감을 준다.

## 4. Transformers are Inherently Succinct (ICLR 2026 Outstanding Paper 🏆)

**arxiv**: [https://arxiv.org/abs/2510.19315](https://arxiv.org/abs/2510.19315)
**발표일**: 2025년 10월 (ICLR 2026 Outstanding Paper 수상)
**코드**: 없음 (이론 논문)
**페이지**: 약 13페이지

### 초록 요약
Transformer의 표현력을 "간결성(succinctness)"이라는 새로운 관점으로 분석한 이론 논문. Transformer가 동일한 개념을 표현할 때 유한 오토마타(finite automata)보다 이중 지수적으로, RNN과 선형 시제 논리(LTL)보다 지수적으로 더 간결하게 인코딩할 수 있음을 증명한다.

### 추천 이유
1. ICLR 2026 Outstanding Paper로 선정된 만큼 올해 가장 중요한 이론 논문 중 하나이며, "왜 Transformer가 강력한가?"에 대한 근본적 답을 제시한다.
2. 지난주 추천한 "Understanding Transformers" 논문의 자연스러운 심화 단계로, Attention 메커니즘을 넘어 아키텍처 자체의 이론적 우위를 이해할 수 있다.
3. 수식이 많지만 핵심 메시지("Transformer는 같은 것을 훨씬 짧게 표현한다")는 명확해서, 전체를 완독하지 않아도 Abstract + Introduction만으로 큰 인사이트를 얻을 수 있다.
