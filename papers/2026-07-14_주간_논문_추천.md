## 1. HopRAG: Multi-Hop Reasoning for Logic-Aware Retrieval-Augmented Generation
**ACL 2025 Findings · 본문 ~10p · 코드 공개 ✅**

**초록 (요약)**: 기존 RAG의 검색기는 어휘·의미 유사도에 집중해 논리적 관련성을 놓친다. HopRAG는 인덱싱 시 텍스트 청크를 정점으로, LLM이 생성한 pseudo-query를 간선으로 하는 passage graph를 구축하고, 검색 시 retrieve-reason-prune 메커니즘으로 유사 passage에서 출발해 멀티홉 이웃을 탐색한다. HotpotQA·MuSiQue·2WikiMultiHopQA에서 기존 dense retriever 대비 답변 정확도 +76.78%, 검색 F1 +65.07%.

**추천 이유**
1. 지금 만들고 있는 HotpotQA 멀티홉 검색 파이프라인과 데이터셋·문제 설정이 정확히 일치 — supporting facts가 왜 유사도 검색만으로 안 잡히는지에 대한 답.
2. 현재 구현한 "검색→재정렬" 구조의 다음 단계(그래프 탐색형 검색)를 보여줘 프로젝트 확장 아이디어로 직결.
3. retrieve-reason-prune은 W2의 run_agent 설계(언제 더 검색할지 결정)에 그대로 참고 가능.

- arXiv: https://arxiv.org/abs/2502.12442
- 코드: https://github.com/LIU-Hao-2002/HopRAG
- 한글 해설: 못 찾음 (ACL Anthology: https://aclanthology.org/2025.findings-acl.97/)

## 2. Search-R1: Training LLMs to Reason and Leverage Search Engines with Reinforcement Learning
**COLM 2025 · 본문 ~13p (부록 포함 31p — 본문만 읽으면 충분) · 코드 공개 ✅**

**초록 (요약)**: 추론 중 검색 엔진을 쓰라고 프롬프팅하는 것은 최적이 아니다. Search-R1은 LLM이 단계별 추론 중 스스로 (여러 번의) 검색 쿼리를 생성하도록 RL로 학습시키는 프레임워크로, retrieved token masking으로 학습을 안정화하고 단순 outcome 기반 보상만 사용한다. 7개 QA 데이터셋(HotpotQA 포함)에서 RAG 베이스라인 대비 Qwen2.5-7B +41%, 3B +20%.

**추천 이유**
1. "에이전트가 언제·몇 번 검색할지 스스로 결정"하는 Agentic RAG의 대표 논문 — W2 run_agent 연결 작업의 개념적 기반.
2. Qwen + veRL 기반 코드가 잘 정리돼 있어 QLoRA 파인튜닝 경험과 연결해 읽기 좋음.
3. 프로젝트 후보였던 '에이전트'와 '파인튜닝' 방향을 한 편으로 커버하는 가성비.

- arXiv: https://arxiv.org/abs/2503.09516
- 코드: https://github.com/PeterGriffinJin/Search-R1
- 한글 해설: https://facerain.me/nonmun-ribyu-search-r1-training-llms-to-reason-and-leverage-search-engines-with-reinforcement-learning/

## 3. GRADE: Generating multi-hop QA and fine-gRAined Difficulty matrix for RAG Evaluation
**EMNLP 2025 Findings · 본문 ~10p · 코드·데이터 공개 ✅**

**초록 (요약)**: 기존 RAG 평가는 실제 시나리오의 구조적 복잡성과 다단계 추론을 간과한다. GRADE는 난이도를 (1) 추론 깊이(홉 수), (2) 질문-근거 간 의미적 거리 두 축으로 모델링하고, 뉴스 기사에서 지식 그래프를 추출·증강해 난이도 제어된 멀티홉 QA 데이터셋을 합성한다. 핵심은 생성기·검색기 양측 난이도를 결합한 2D 난이도 매트릭스로, RAG 성능의 세분화된 분석을 가능하게 한다.

**추천 이유**
1. 캘린더에 적어둔 "RAG 평가 계열" 그 자체 — 내 RAG가 몇 홉짜리 질문에서 무너지는지 진단하는 프레임 제공.
2. HotpotQA 실험에서 "쉬운 질문/어려운 질문"을 나눠 리포트하면 프로젝트 결과물의 설득력이 크게 올라감.
3. 최신(EMNLP 2025) 평가 방법론이라 포트폴리오 차별화 포인트로 좋음.

- arXiv: https://arxiv.org/abs/2508.16994
- ACL Anthology: https://aclanthology.org/2025.findings-emnlp.236/ (코드는 논문 내 GitHub 링크 참조)
- 한글 해설: 못 찾음

## 4. RAGAS: Automated Evaluation of Retrieval Augmented Generation
**EACL 2024 · 8p · 코드 공개 ✅ (ragas 라이브러리)**

**초록 (요약)**: 정답 레퍼런스 없이(reference-free) RAG 파이프라인을 평가하는 프레임워크. Faithfulness(생성 답변이 검색 컨텍스트에 근거하는가), Answer Relevance(질문에 적절한가), Context Relevance(검색 결과가 필요한 정보만 담는가)를 LLM 기반으로 자동 측정한다.

**추천 이유**
1. 8페이지로 가장 짧고, `pip install ragas` 후 이번 주 파이프라인에 바로 붙여볼 수 있는 실전용.
2. GRADE(난이도 진단)와 상호보완 — RAGAS는 컴포넌트별(검색 vs 생성) 품질 진단 담당.
3. 한글 자료가 가장 풍부해 학습 부담이 낮고, 면접에서도 자주 나오는 표준 도구.

- arXiv: https://arxiv.org/abs/2309.15217
- 코드: https://github.com/explodinggradients/ragas
- 한글 해설: [우아한 스터디 — RAGAS 정리 (velog)](https://velog.io/@judy_choi/%EC%9A%B0%EC%95%84%ED%95%9C-%EC%8A%A4%ED%84%B0%EB%94%94-RAGAS-RAG-%ED%8C%8C%EC%9D%B4%ED%94%84%EB%9D%BC%EC%9D%B8-%ED%8F%89%EA%B0%80-%ED%94%84%EB%A0%88%EC%9E%84%EC%9B%8C%ED%81%AC) · [슈퍼브AI — Ragas 스코어 가이드](https://blog-ko.superb-ai.com/rag-pipeline-performance-metrics-ragas-score-guide/) · [랭체인 노트 — RAGAS 평가 실습](https://wikidocs.net/259205)
